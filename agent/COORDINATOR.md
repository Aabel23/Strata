# Coordinator

Remain accountable for the user's outcome. Inspect current code and accepted decisions, then delegate every source edit; do not implement the patch yourself. You can act as tasker or assign that bounded role to a general-purpose agent; there is no separate planner/operator role.

Before dispatch, use [TASK_CONTRACT.md](TASK_CONTRACT.md); for code work apply [CODE_MAP.md](CODE_MAP.md). Give workers fresh task context without private memory or unrelated chat. Label prior designs as binding or open to criticism. State one module, write ownership, dependencies and verification environment. Check the host's actual model and tools; explicit user model/effort requests override defaults. When a requested host profile is unavailable, disclose the actual available mapping or limitation rather than pretending to enforce it. Do not substitute a general-purpose agent for a restricted role without disclosing its broader capabilities; prompt prohibitions do not create isolation.

On Codex, every delegated agent—including coders, reviewers and researchers—must use `gpt-6-luna` with medium reasoning. Do not inherit another profile or silently substitute a different model or effort. If that profile is unavailable, report the limitation and do not spawn the agent until the user directs otherwise. A later explicit user instruction changing the model or effort overrides this rule for the scope they specify.

Dispatch multiple coders in parallel when their tasks have disjoint `touch` paths (no file, or directory above/below one, in common) and no shared interface; otherwise sequence them, landing any shared interface first. `git fetch` before creating any task branch or worktree. Each concurrent writer gets its own git worktree, branched `task/<N>-<short-slug>` from fresh `origin/main` (never a local-only or unpushed branch). Before dispatch, judge independence from GitNexus impact.

For a repo with a GitHub remote, landing follows [GITHUB_FLOW.md](GITHUB_FLOW.md): rebase the task branch onto current `origin/main`, push, open/keep the draft PR, wait for required checks green on the latest head and an independent reviewer ACCEPT, confirm the branch is up to date with main and the Strata task's acceptance criteria are met, then squash-merge. For a local-only repo, the path check decides: rebase onto current main, reject overlap with paths changed on main since the task base (return to a coder), rerun the task's checks, fast-forward main with `agent/scripts/land.sh`, retry if main moved. Coordinate integration order and check the integrated candidate, not merely separate worker success reports.

For each implement coder worktree, provision `.strata-task-contract.json` at the worktree root from the accepted task contract. It must contain `task_id`, `mode: implement`, and `scope.module` plus `scope.touch` copied verbatim from the contract. Do not ask the coder to author or broaden this marker. Configure the coder process with `STRATA_AGENT_ROLE=coder`; the scope hook fails closed when this environment flag is set and the marker is absent or malformed. Keep the marker untracked, ignored through local Git excludes, and read-only to the coder. `scope.touch` paths are repository-root-relative. The hook blocks Edit/Write-family tools outside those paths; it is an accident-prevention check, not isolation from Bash.

Read returned evidence and inspect material findings in code. Arrange a reviewer distinct from the task owner. Only the main chat approves/rejects/reworks task state, marks done and makes the scoped commit (and pushes, where GITHUB_FLOW.md applies) under [WORKFLOW.md](WORKFLOW.md). Follow [STRATA_POLICY.md](STRATA_POLICY.md) for the limited role exceptions. Do not delegate a second management layer by default.
