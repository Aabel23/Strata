# Strata task pipeline

Use the canonical [GitHub flow](../../GITHUB_FLOW.md) and [task contract](../../TASK_CONTRACT.md). This skill is the short operational path for a single approved task. Do not sweep the whole board for a scoped request.

1. Read the task once through Strata. Require an approved or already-owned task, completed dependencies, acceptance criteria, and `scope.touch`. Prefer a specific `scope.module`; legacy tasks without one use the project id. Record the task id and project root. Use the smallest relevant code context; fetch more only when a named acceptance check needs it.
2. Fetch `origin/main`. If the main checkout is clean, on `main`, and no sibling task is active in that project, fast-forward it with `git pull --ff-only origin main`; otherwise leave the checkout intact and base the task worktree directly on fresh `origin/main`.
3. Name the branch `action/scope/work_t<ID>`. `action` is `feat`, `fix`, `refactor`, `docs`, `test`, or `chore`; `scope` is the normalized `scope.module` or project id; `work` is a short normalized task title. Use `spec.action` when set, otherwise `fix` for issues and `feat` for tasks. Create the worktree at `<project parent>/.strata-worktrees/<project>/<branch>`. The branch path and folder path match. Retries reuse the existing branch; never rename a branch merely because a title changed.
4. Bind the agent to the task before work: task id, branch, worktree, parent session, and allowed paths form one run record. A task agent starts in that worktree. Before spawning a delegated subagent for a task, provision that task's worktree and pass its absolute path and contract; a lifecycle hook only reports the child and cannot move its working directory. The Agents viewer matches CLI sessions under known worktrees to their task, links child processes by ancestry, and links native subagents through lifecycle hooks. If an external terminal is not owned by Strata, show its card but do not promise live attachment.
5. Give the worker only the task contract and relevant files. The coordinator creates `.strata-task-contract.json` from the accepted scope. Worker edits stay in `scope.touch`. CI files under `.github/workflows/` require both explicit `scope.touch` and `ci_change_approved: true` in the approved task. The worker cannot create a PR, delete a remote branch, force push, or modify GitHub settings. The supervised runner owns the push after verifying the branch, changed paths, Git refs, and configuration.
   Run disjoint `scope.touch` lists in parallel; serialize tasks whose paths overlap or whose scope is unspecified. This avoids conflicting edits while allowing separate worktrees to make progress together.
6. Run the task's verification, capture exact results, commit scoped files, and push the branch. Never stage with `git add -A` from a checkout containing unrelated work. On a failed check or unexpected diff, keep the task in `doing` with a short error and resume on the same branch.
7. After push, mark the task `review` with commit SHA, branch, worktree and verification evidence. CI is expected to check that exact head and create or update one PR into the configured integration branch only after checks pass. The agent observes the PR; it does not create it. A missing CI workflow means the task remains awaiting PR, not silently approved. Merge only under the separate review gate; never delete a remote branch as cleanup.

Read [CI bot contract](references/ci-bot-contract.md) when configuring CI or diagnosing a missing PR. Read [session binding](references/session-binding.md) when adding a session provider, subagent hook, or task-card association.

The `github_guard.py` and `ci_edit_guard.py` hooks cover Claude and Codex tool calls when registered; Claude coders also use `scope_guard.py`. `agent_guard.py` applies to supervised Claude task runs. Codex requires review/trust of new hooks through `/hooks` before activation. Hooks are not a security boundary: branch protection, separate bot credentials and the runner's pre-push verification enforce the remote side. Shell scripts can bypass a path parser, so worker permissions must also be limited by worktree and credentials.
